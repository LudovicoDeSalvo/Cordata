# Pi and Herdr verification (researched 2026-09-29)

Purpose: verify the platform claims in `base-docs/` against live sources. Web research by a subagent; items marked [U] unconfirmed.

## Pi (earendil-works/pi)

- Real, large. TypeScript, MIT. ~110k stars, created 2025-08. Releases 1–2/week; latest v0.87.1 (2026-09-22). https://github.com/earendil-works/pi
- Monorepo packages: `pi-coding-agent` (CLI), `pi-agent-core` (agent runtime, tool calling, state), `pi-ai` (multi-provider LLM API: OpenAI, Anthropic, Google, more), `pi-tui`, `pi-durable`, `pi-telemetry`, `chord` (app-composition runtime: services, replicated state, RPC, plugins).
- All extension hooks named in the spec exist (verified in `packages/coding-agent/src/core/extensions/types.ts`): `project_trust`, `session_start`, `resources_discover`, `input`, `before_agent_start`, `agent_start/end/settled`, `turn_start/end`, `context`, `before_provider_request`, `after_provider_response`, `tool_call`, `tool_result`, `session_before_compact`, `session_compact`, `session_shutdown`, `pi.setActiveTools()`, `pi.appendEntry()`.
- Extra hooks not in spec: `context_with_system` (handler owns full prompt + tool declarations), `agent_before_settle`, `before_provider_headers`, `provider_stream_event`, `message_*`, `tool_execution_*`, `session_compact_failed`, `session_before_switch/fork/tree`, `model_select`, `cache_warming_decision`, `mcp_servers_change`, `user_bash`.
- `context` CAN replace messages (system prompt and tool state restored by Pi after handler). `before_provider_request` CAN replace payload. `after_provider_response` = status + headers only.
- Compaction: auto when `contextTokens > contextWindow - reserveTokens` (reserve 16,384; keepRecentTokens 20,000). `session_before_compact` can cancel or supply custom compaction object.
- Sessions: JSONL under `~/.pi/agent/sessions/`, tree via id/parentId (in-file branching), entry types incl. `compaction`, `context_edit`, `custom` (from `appendEntry`).
- No sandbox (docs explicit). Project trust gates project-local extensions only.
- Subagents/background: not in official docs; third-party extensions (`tintinweb/pi-subagents`, `pi-tasks`).
- SDK: `createAgentSession()`, `AgentSession.prompt/steer/followUp`, injectable `ModelRuntime`, `SessionManager` (persistent or in-memory), `ResourceLoader` (full control over extensions/skills/prompts/context files), `customTools`. RPC mode and JSON event-stream mode exist.
- Auth: API keys; Anthropic also `ANTHROPIC_OAUTH_TOKEN` / `ANTHROPIC_AUTH_TOKEN`. Subscription-plan OAuth (Claude Pro/Max) not documented [U].

### pi-durable / Pico5 (important)

- `@earendil-works/pi-durable`: "Durable conversation, task, and document runtime". Storage backends: memory, JSONL (Node, fsync option), SQLite (Node, WAL). Conformance + benchmark test utilities. Shipped as library.
- Design doc `packages/durable/docs/pico-v5.md` is normative: "Pico5 is not implemented yet, but implementations must expose this shape."
  - Conversations: transcript scopes, fork hierarchically, immutable history via parent pointers; own entries, tasks, documents.
  - Tasks: durable state machines with phases; checkpoint between phases; reconcile to pending on reopen; dependency via `after` field (sub-task DAG); background tasks are traversal boundaries.
  - Documents: mutable JSON state via Chord op-based deltas; scoped to session/conversation/task; fork policies asOf/current/initial.
  - Records: immutable persisted entries (conversations, entries, tasks, submissions) with sequence + id. "Only committed state is observable."
  - Replay: tool memos + durable arguments.
  - Integration: process-local registry (tools, tasks, hooks, system-prompt sections), not RPC.
  - Not covered (per summary): verification/acceptance, artifact/git binding, worktrees, external-effect reconciliation.

## Herdr (herdrdev/herdr)

- Real, large. Rust, Apache-2.0. ~41k stars, created 2026-03. Herdr, Inc. ($6M seed; "Herdr Cloud" forthcoming). Latest v0.9.2 (2026-09-29). https://github.com/herdrdev/herdr https://herdr.dev/
- Background server + agent-aware terminal multiplexer: workspaces/tabs/panes, session persistence, multi-machine via SSH, per-pane agent status.
- Socket API (NDJSON over Unix socket): all 12 methods claimed in the spec exist. Also `events.wait`, `agent.list/get/explain/send_keys/rename/focus`, `pane.split/send_text/send_keys/wait_for_output/report_agent/report_agent_session/release_agent`, `layout.*`, `plugin.*`, `integration.*`, `server.agent_manifests`.
- `agent.wait` states: idle, working, blocked, done, unknown. Detection is screen-based via per-agent TOML manifests (remotely updated). Integrations that report state directly (Pi, OpenCode, Kimi, OMP) override screen detection. Docs admit misclassification cases (issues #4557, #4641, #2711). Codex "may stay unknown".
- Pi integration: installs `~/.pi/agent/extensions/herdr-agent-state.ts`, reports session identity and authoritative lifecycle state. Claude Code/Codex report identity only.
- Supported agents: Claude Code, Codex, Copilot CLI, Cursor Agent, OpenCode, Pi, OMP, Droid, Devin, Kimi, Kilo, Hermes, Qoder, Qwen, Letta, MastraCode, Grok, Antigravity, Amp, Kiro, Maki, Gemini CLI, Cline, more.
- Plugins: `herdr-plugin.toml` (startup hooks, actions, event hooks, pane entrypoints, link handlers), any argv command. Marketplace claims ~1,400 plugins.
- Pi + Herdr together: community bridges `AndrewJacop/pi-herdr`, `kodicw/pi-herdr`; official Pi state extension.

## Implication for Cordata

- The spec's "small projects" risk assessment is wrong: both are large. Remaining risk is Pi API churn (weekly releases, v0.x).
- Pi is building its own durable task runtime (Pico5). Cordata must either build on it or justify duplication.
